# Current intent conversation procedure

This is a replaceable part of L1. Future interview tools or skills may improve understanding;
they supply evidence and proposals, while the human retains control of the goal and delegation.

Start with what the user has already said. Reflect the intended outcome in concrete terms and
identify the few uncertainties that would change the work. Use examples, existing project
context and read-only research when useful. Do not run a universal questionnaire or repeatedly
ask questions already answered. Keep talking while the user is refining their thinking.

Maintain a draft of the goal, observable success criteria, priorities, constraints, non-goals,
relevant original excerpts, delegated decisions and human-only boundaries. Before handoff also
resolve the workspace and finite execution guards. Numerical guards are implementation choices
to disclose and review, not facts to invent about the user's wishes.

Propose the local execution scope needed for the intended workflow. For routine Go work this may
include trusted project edits, exact tests, local task commits, worktree creation, integration and
safe cleanup. Record the actual paths, branch scope and commands. Describe excluded or unresolved
operations only when relevant. Present intent and this attachment together so the user can approve
one concrete handoff rather than answer a series of implementation permissions.

Preserve what is known, what is tentative and what the user has actually approved. Use
`ouroboros:approve` for the reviewed handoff. Continue listening afterward; conversation never
becomes unavailable just because execution has begun. Formal intent/authority changes follow the
existing amendment process and do not retroactively authorize work.
